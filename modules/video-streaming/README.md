# Video streaming source matrix (VS-01)

This is a source inventory for VS-01, not a capability admission or qualification record. The 17-row denominator is the exact set of PDP-0 leaves listed under `media.stream.*` in [`capabilities.yaml`](../../.product-experience/pdp-0-product-truth/capabilities.yaml#L100-L116). The remaining-surfaces plan records the same denominator and marks the video surface `NO_IMPLEMENTATION_ADMITTED` ([VS plan entry](../../docs/implementation/MEDIA-BACKEND-REMAINING-SURFACES-2026-10-30.md#L149-L160)).

The HTTP contract exposes five generic stream routes, not one route per capability: open, read, connect/reconnect, frame submit/acknowledgement, and close ([`media.yaml`](../../contracts/openapi/media.yaml#L699-L915)). The routes use the canonical `MediaRuntime` session store. Video helpers in this module do not create another durable session store or establish end-to-end stream success. For implemented rows below, “shared runtime” means the generic operation exists; it does not establish a qualified video provider, formal PDP admission, or an external transport.

## Video timing and capture boundary

[`VideoFrameTimebase`](src/main/java/com/ghatana/video/streaming/VideoFrameTimebase.java) keeps capture PTS, presentation PTS, declared rational timebases, clock identity, discontinuity, codec identity and presentation mapping explicit. Unknown values remain unknown; the adapter does not infer a clock or normalize VFR timestamps. [`VideoVfrTransportIntegrationTest`](src/test/java/com/ghatana/video/streaming/VideoVfrTransportIntegrationTest.java) exercises source timing and frame reconciliation with fixtures; it is not real external-transport qualification.

[`VideoCaptureProfile`](src/main/java/com/ghatana/video/streaming/VideoCaptureProfile.java) qualifies only `IN_PROCESS`; WebRTC, adaptive HTTP, HLS and DASH remain unqualified. Its immutable captured-artifact value and the in-process frame roundtrip do not identify or qualify a camera/capture source adapter. No video capture/provider adapter binding to the canonical `MediaStreamingProvider` was identified in this source review. Treat video-specific provider admission and real capture semantics as **unresolved / not established** until a source-owned binding and evidence exist.

`VideoStreamSession` is a bounded wire encode/decode helper. It does not own tenant session state, provider lifecycle, capture, or durable acknowledgement. Canonical session storage and state transitions remain with `MediaRuntime` through `MediaStreamSessionStore`.
