# Video streaming source matrix (VS-01)

This is a source inventory for VS-01, not a capability admission or qualification record. The 17-row denominator is the exact set of PDP-0 leaves listed under `media.stream.*` in [`capabilities.yaml`](../../.product-experience/pdp-0-product-truth/capabilities.yaml#L100-L116). The remaining-surfaces plan records the same denominator and marks the video surface `NO_IMPLEMENTATION_ADMITTED` ([VS plan entry](../../docs/implementation/MEDIA-BACKEND-REMAINING-SURFACES-2026-10-30.md#L149-L160)).

The HTTP contract exposes five generic stream routes, not one route per capability: open, read, connect/reconnect, frame submit/acknowledgement, and close ([`media.yaml`](../../contracts/openapi/media.yaml#L699-L915)). The routes use the canonical `MediaRuntime` session store. `MediaRuntimeCanonicalVideoStreamFramePort` binds decoded frames to the store's tenant/principal, connection token, reconnect generation, lease, CAS version and durable ACK cursor. It preserves the existing video wire header and does not treat its legacy timestamp as source PTS. Video helpers in this module do not create another durable session store or establish end-to-end stream success. For implemented rows below, “shared runtime” means the generic operation exists; it does not establish a qualified video provider, formal PDP admission, or an external transport.

## Video timing and capture boundary

[`VideoFrameTimebase`](src/main/java/com/ghatana/video/streaming/VideoFrameTimebase.java) keeps capture PTS, presentation PTS, declared rational timebases, clock identity, discontinuity, codec identity and presentation mapping explicit. Unknown values remain unknown; the adapter does not infer a clock or normalize VFR timestamps. [`VideoVfrTransportIntegrationTest`](src/test/java/com/ghatana/video/streaming/VideoVfrTransportIntegrationTest.java) exercises source timing and frame reconciliation with fixtures; it is not real external-transport qualification.

[`VideoCaptureProfile`](src/main/java/com/ghatana/video/streaming/VideoCaptureProfile.java) qualifies only `IN_PROCESS`; WebRTC, adaptive HTTP, HLS and DASH remain unqualified. The launcher frame adapter bridges the helpers to an already selected canonical `MediaStreamingProvider`; it does not introduce a camera source adapter or qualify capture semantics. Treat video-specific source admission and real capture as **unresolved / not established** until a source-owned binding and evidence exist.

`VideoStreamSession` is a bounded wire encode/decode helper. It does not own tenant session state, provider lifecycle, capture, or durable acknowledgement. Canonical session storage and state transitions remain with `MediaRuntime` through `MediaStreamSessionStore`.

`CanonicalVideoStreamFramePort` is the module boundary for that owner: it requires a trusted tenant/principal/purpose binding, durable reconnect revision, exact store CAS version, ACK cursor, and lease expiry before a runtime can accept a helper frame. The port itself is fail-closed and stores no state. The launcher adapter is bound to `MediaRuntime`; `VideoFrameReconciler` and `GuardedVideoStreamSession` remain local helpers. EOS acceptance transitions the session to `DRAINING` and does not claim provider finality. `OfferFeedback` reports provider buffer/backpressure only when available. The helper's legacy `timestampMillis` remains unqualified and must not be treated as source PTS.

## Authenticated gRPC source capture

`GrpcVideoSourceCapture` accepts a transport-neutral `AuthenticatedGrpcSource` seam. Trusted source readback binds the exact source version, source cursor, and next Media sequence; a bounded batch is capped at 128 frames and 16 MiB, reordered by Media sequence, and offered only as a contiguous prefix through `CanonicalVideoStreamFramePort`. Authorization is re-read before every frame and EOS. Unknown, denied, and explicitly revoked readback stop offers with distinct non-success outcomes. A gap stops at the first missing cursor, backpressure stops later offers, and a lost/null canonical ACK returns `OUTCOME_UNKNOWN` without replay.

Each frame carries exact rational presentation PTS or an explicit `UNKNOWN` timestamp. Known PTS values must use the same clock/timebase and remain nondecreasing within the batch. The legacy `timestampMillis` is passed through as its separate wire field; it never supplies or replaces PTS. No concrete authenticated gRPC transport binding is wired, so real source capture remains unavailable until a real client and trusted readback implementation are supplied. The canonical ACK persists only Media sequence acceptance; it does **not** durably persist source cursor, source version, or PTS. A successful frame ACK is not a durable provenance receipt or provider-finality result.
