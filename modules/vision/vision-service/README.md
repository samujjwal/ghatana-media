# Media Vision service

This Media-owned module supplies the Vision gRPC boundary, bounded image/video preparation, source-raster geometry and conditional detector integration. Its consumers are Media runtime adapters, Multimodal and authorized gRPC clients. Product intent remains in the repository PDP sources; this guide describes implementation, not provider qualification or task acceptance.

## Boundary and architecture

The entry point is `com.ghatana.audio.video.vision.grpc.VisionGrpcServer`, in Gradle project `:services:media:modules:vision:vision-service`. [vision_service.proto](src/main/proto/vision_service.proto) owns the 10 wire methods and field numbers; generated Java is build output. [WAVE2-RPC-CAPABILITY-MATRIX](WAVE2-RPC-CAPABILITY-MATRIX.md) indexes method/capability relationships. The [Wave 2 plan](../../../docs/implementation/MEDIA-BACKEND-MODALITY-WAVE2-EXECUTION.md) owns VIS-01–12 acceptance.

`VisionGrpcService` validates/authenticates requests. `ProductionVisionGrpcService` validates `VisionModelProfile`, requires trusted admission, and only then initializes `YoloV8Adapter`. `VisionProviderAdmission.requireAdmitted` currently rejects production initialization because a trusted license/provider admission source is absent. File metadata and a matching digest do not make the detector available.

`BoundedImageDecoder`, EXIF/source-raster transforms and `VideoFrameExtractor` provide Media-specific input preparation. When the authenticated host broker is configured, the current narrow admitted operation is a source-only FFmpeg probe over one 0440 sentinel file using the `file` protocol whitelist and null muxer to stdout; requests with writable output remain rejected until a bounded output-transfer protocol is added. The Media process connects through `GHATANA_MEDIA_VISION_OCI_BROKER_SOCKET` and a separate peer-owned, owner-only `GHATANA_MEDIA_VISION_OCI_BROKER_TOKEN_FILE`; the client token is a separately provisioned 0600 copy of the broker's secret. Set `GHATANA_MEDIA_VISION_OCI_BROKER_REQUIRED=true` where direct Docker fallback is disallowed. The Media-side `GHATANA_MEDIA_VISION_WORKER_IMAGE` must match the broker's `MEDIA_OCI_BROKER_VISION_IMAGE`. The broker requires a private 0600 server token in its broker-owned 0700 nonce-state directory, a source root, an output root (future output transfer only), a dedicated `MEDIA_OCI_BROKER_STAGE_ROOT` (real directory, broker-owned, 0700, with broker/root-owned safe ancestors, outside and non-overlapping with source/output roots), image allowlist, worker UID/GID, allowed peer user and numeric `MEDIA_OCI_BROKER_ALLOWED_PEER_GID`. The worker GID and allowed peer GID must be the same dedicated broker/peer group. Both the broker service and Media peer must belong to that group (primary or supplementary membership); source access fails closed if the broker cannot traverse and hash the source. For future source-backed work, the source root and child directories must be peer-owned by the worker UID, use the shared GID and mode 02750; source files must use that UID/GID and mode 0440. These modes grant no access to other users. The worker runs under the configured UID/GID. Its socket parent must be broker-owned, peer-group-owned and mode 02710; the socket must be broker-owned, peer-group-owned and mode 0660. The daemon verifies these identities/modes at startup and checks the actual Unix socket peer username through `SO_PEERCRED` before reading every request. The group gates socket access; the kernel-authenticated username check narrows accepted requests to the configured peer. Run the broker under an OS account distinct from the allowed Media peer; identity checks do not trust the overridable JVM `user.name` property. Before mounting a bounded source, the broker copies it into its private stage root and verifies the staged SHA-256; it retains staged input if container removal cannot be confirmed. A retained snapshot blocks later broker work and restart until an operator reconciles the stage root; there is no automatic purge. Its `MEDIA_OCI_BROKER_VISION_PROFILE_ID`, `MEDIA_OCI_BROKER_VISION_IMAGE` and `MEDIA_OCI_BROKER_VISION_TOOLCHAIN_VERSION` values bind requests to one allowlisted digest-pinned image and declared toolchain profile. The request cannot select another image.

The worker runs with a read-only root filesystem, no network, dropped capabilities, no new privileges and a read-only snapshot mount. Although the low-level command builder can describe a bounded output mount, the authenticated request handler currently rejects every writable output mount: the 128 KiB JSON response cannot return output files safely under Media ownership, and binding the caller's mutable directory would leave a path replacement race. Read-only probes can run; frame extraction and audio demux through this broker remain unavailable until an authenticated bounded output-transfer protocol is added. For admitted probes, the host command applies 1.5 GiB memory and swap ceilings, 2 CPU, 32 PIDs, 64 file descriptors, and the caller's wall timeout; timeout triggers kill and removal attempts. A disconnect or cleanup/response ambiguity after request transmission remains `UNKNOWN` until reconciliation; the current protocol has no cancellation operation. Before mount, the broker copies the bounded source into its private stage root and verifies the snapshot SHA-256 against the request digest, closing the pathname hash-to-mount race. It deletes the snapshot only after confirmed container removal and retains it on unknown cleanup. Retained snapshots have no restart reconciliation; a retained entry blocks later work and restart until an operator reconciles it. The code and fake-runner checks do not establish deployment qualification on a named production host or hard host isolation. Without broker configuration, codec execution follows the local OCI path unless broker-required mode is set. Generic OCR belongs to Document Intelligence. Reuse Media runtime contracts and Shared identity/observability; do not add a second job, policy or OCR engine here.

`bash scripts/qualification/run-wave2-vision-oci-checks.sh broker` is external-broker-only: it never builds an image or starts a daemon. It requires preprovisioned socket/client-token/image, peer identity/group, worker UID/GID, broker identity, stage root and worker source/output roots using `GHATANA_MEDIA_VISION_OCI_BROKER_TEST_*` variables. The peer must belong to the configured worker/shared GID as a primary or supplementary group; the worker GID must equal the peer/socket GID. Source and output roots must be worker-owned, shared-group-owned mode 02750; source files must use that UID/GID and mode 0440. The test selector runs one authenticated source-only sentinel probe and one negative request proving writable output is rejected; it exercises source validation and staging but does not qualify media decoding or output return. The selector is disabled when inputs are absent; the script fails with missing prerequisites and rejects skipped reports. The peer owns the 0600 client-token copy; the broker retains its separate 0600 server token and 0700 journal/stage roots. The test checks stage-root metadata without listing the broker-private directory; its broker/root-owned ancestors must permit peer traversal without peer write (for example, mode 0710), while the stage directory remains 0700. Daemon startup remains responsible for checking the stage root is empty.

`YoloXNanoAdapter` is a separate experimental adapter with its own 416x416 preprocessing and `[1,3549,85]` decoder; it does not reuse the YOLOv8 parser. The catalog digest identifies the official release bytes only. Provider admission, ONNX export lineage, COCO image/label rights and model quality remain unverified.

The host broker stores a durable HMAC-protected nonce replay journal beside its server token file. The token's parent directory must be broker-owned, mode `0700`, persistent across daemon restarts, and separate from socket, source, output and worker-stage roots; the server token remains a regular broker-owned `0600` file. The peer receives a distinct peer-owned `0600` client-token file containing the same secret; the daemon never reads that peer copy. Journal creation and compaction require atomic rename and directory `fsync`. A backward wall-clock jump fails closed until the clock is corrected and the broker is restarted. The live replay set is capped at 65,536: at capacity, fresh requests are rejected until signed timestamps expire; live replay evidence is never evicted to make room. Changing the token without a journal migration fails integrity validation, so token rotation must be planned as an offline state migration and must not delete replay evidence ad hoc.

## Configuration and extension

`VISION_GRPC_PORT` defaults to 50054. Transport security follows the shared Media gRPC policy. Model preflight reads `VISION_MODEL_PATH`, `VISION_MODEL_NAME`, `VISION_MODEL_VERSION`, `VISION_MODEL_SHA256`, `VISION_MODEL_LICENSE`, `VISION_MODEL_CLASSES` and `VISION_MODEL_DEVICE`; [VisionModelProfile](src/main/java/com/ghatana/audio/video/vision/model/VisionModelProfile.java) owns validation. Confidence/NMS thresholds come from `VISION_CONFIDENCE_THRESHOLD` and `VISION_NMS_THRESHOLD`, defaulting to 0.5/0.4 within `[0,1]`.

The profile accepts only CPU device metadata and bounds a regular local ONNX file to 2 GiB; this is preflight, not admission. The module does not automatically download weights. Extend existing detector/runtime interfaces, preserve wire compatibility and test positive, boundary and failure behavior. See [design](../../../docs/DESIGN.md) and [operations](../../../docs/OPERATIONS.md).

## Usage examples and testing

From the Media root, with Java 27/Shared prerequisites in [TESTING](../../../docs/TESTING.md):

```sh
./gradlew -Pghatana.media.compositeScope=FOCUSED \
  -Pghatana.media.focusedModules=vision \
  :services:media:modules:vision:vision-service:test \
  --tests '*VisionGrpcServiceInProcessIntegrationTest'
```

This suite supplies controlled dependencies; it is not a real model benchmark. Missing/invalid model metadata must reject production startup. Even valid local metadata reaches `PROVIDER_NOT_ADMITTED` until trusted admission is integrated; no generated detection is expected on that path.

Native work uses `mac-native` and `linux-arm64-native` with the source-pinned tools in [TESTING](../../../docs/TESTING.md). Required checks include malformed/oversized input, path/codec restrictions, timeout/kill/cleanup, source clocks/ROI and provider absence. Real mAP/quality/resource measurements need exact qualified model/input/environment. [EVIDENCE](../../../docs/EVIDENCE.md) defines artifacts and repeatability; no test pass is asserted here.

## Non-functional scope

Rights, source ownership, tenant isolation and biometric authorization apply before effects; diagnostics must not expose content or model paths. Native processing needs hard resource controls or rejection. GUI accessibility is N/A for this backend; locale, script and scene-text semantics remain applicable. AI/ML quality, weights/corpus provenance and dependency/codec licensing remain qualification obligations.
