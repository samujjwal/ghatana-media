## Completion rubric and reuse rules

1. Select one area's **one concrete next consumer outcome**, not a broad feature family. Inspect the named source before coding and reuse existing working modules. Document the exact input/operation/output and limitations in its permanent surface README.
2. Implement the smallest end-to-end path including a **real public consumer** (Java package/CLI/SDK/browser), then exact output bytes or durable state. Synthetic fixtures prove only controls and failure semantics, not model/quality or human approvals.
3. Run a **focused changed-source test** and its affected contract/consumer tests. Use `node scripts/check-media-surface-delivery.mjs --affected=<base-commit>` to print changed-source areas and the smallest already-defined test selectors; it never executes tests or claims a PASS. Use Gradle incremental/build cache, pnpm/Vitest focused files, and Rust incremental compilation. Do not force `--rerun-tasks`. Reuse previous passing test results only if the transitive source, test files/fixtures, dependency locks, tool versions, architecture, OS, configuration and signed external input identity are unchanged. Real volatile external effects and measurements must be checked on their actual current host.
4. Preserve a local developer test-pass cache keyed by `{checkId, source+transitive-input hashes, toolchain/OS/arch, provider profile/source revision, test command, test fixture digest}`. A missing/failed/partial or untrusted cache entry **never** skips execution; only a recorded PASS from a real invocation may be reused. Volatile host/provider/measurement checks always use current-host-only execution. The current repository helper accepts complete Node TAP results for deterministic local checks; other runner formats continue to execute normally. See [LOCAL-TEST-PASS-CACHE.md](LOCAL-TEST-PASS-CACHE.md) for the helper and policy. This cache is an efficiency mechanism, **not** a lifecycle/evidence/closure receipt.
5. Do not re-execute a verified source task after unrelated docs/feature changes. If a shared public contract changes, invalidate only affected downstream tests. Run a complete host/business journey once its actual contract is ready; avoid 30 overlapping giant suites in each edit loop.
6. Every task leaves an owner-intent code path, runnable focused test, bounded adverse matrix (auth/tenant/revoke/cancel/timeout/restart/UNKNOWN/resources), a stable caller-visible API/error, short surface documentation, and an observable usable example. No new wave/batch/session-named docs or duplicate product state.
7. A journey remains OPEN until its actual required integrated outcome is exercised; **local usable** must be tracked as an intermediate product fact, not falsely promoted to the whole-task VERIFIED state. The current capability crosswalk contains 469 leaves; family-level implementation classifications are not proof that no usable local code exists.
