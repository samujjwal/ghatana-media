# pnpm source-composite manifest authority

Media's pnpm workspace includes selected packages from sibling repositories for local source-composite development. A sibling package may contain a temporary Kernel `package.yaml` projection next to its canonical npm `package.json`. The projection serves Kernel source tooling; the owning repository's pnpm `readPackage` hook maps it back to npm package metadata for installation and lockfile resolution.

The Media root `.pnpmfile.cjs` delegates only temporary package projections whose exact `repositoryRef` is `ghatana:ghatana-lifecycle` to Lifecycle's `.pnpmfile.cjs`. It does not copy the owner algorithm or alter sibling files. If a recognized Lifecycle projection is present but its owner hook is unavailable, resolution fails with a direct error. Other packages pass through unchanged. Tools packages currently included by Media's workspace use `package.json` directly; Tools temporary projections are outside this workspace's current package set.

Keep dependency and devDependency truth in each owning `package.json`. After changing workspace membership or owner dispatch, run the focused regression and verify the Media lock with the frozen offline check:

```sh
node --test tests/pnpm-workspace-manifest-hook.test.mjs
pnpm install --lockfile-only --frozen-lockfile --offline --ignore-scripts
```
