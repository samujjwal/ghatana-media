## Existing direct reuse evidence

- `launcher/build.gradle.kts` binds the application to Shared `core`, `observability`, `config`, `database`, `security`, `messaging`, and `contracts` artifacts. In standalone mode, `settings.gradle.kts` substitutes these Maven coordinates with projects from the sibling Shared composite build.
- `modules/infrastructure/messaging` and `audio-video-observability` import Shared `MetricsCollector`; this is already an active direct reuse path, not a proposed one.
- `modules/infrastructure/security/build.gradle.kts` declares Shared `security`, `governance`, and `observability`; its `MediaProcessingSecurityValidator` is Media request-policy validation and should not be mistaken for a replacement of the Shared identity/authentication authority.

## Change decision

No runtime code was changed. Current candidates either already use Shared's compatible API or require a transport, persistence, identity-authority, exporter, or semantic binding that is not established by the source inspected. The next useful evidence for the workflow candidate is a minimal Media consumer using the packaged Shared public artifact with the PostgreSQL-backed reservation/lease boundary; the next useful evidence for observability/security is an explicit host and authority binding plus focused adapter contract tests. Those experiments do not imply external owner approval or production readiness.
