This checklist expands the 47-task disposition into the concrete actions, owners, and evidence required to reach the post-PDP goal. It is a work plan, not an owner approval, Lifecycle receipt, migration admission, or release authorization.

## Goal and current position

The goal is to complete the post-definition program without reopening the four `DEV_COMPLETE` definition gates absent a material semantic counterexample: source-backed physical/composition adoption, qualified runtime and product experiences, owner-reviewed dependency and consumer parity, independent acceptance, Lifecycle receipts, and an authorized production cutover/release.

The 47-task disposition contains 7 `LOCAL_COMPLETE`, 8 `LOCAL_COMPLETE_EXTERNAL_REVIEW_PENDING`, 17 `PARTIAL`, 9 `EXTERNAL_PENDING`, 2 `UPSTREAM_NOT_AVAILABLE`, 2 `BLOCKED_DEPENDENCY`, and 2 `DEFERRED` tasks. The 8 locally implemented surface tasks still need owner or independent review. The partial and blocked tasks need the evidence below before they can be called complete.

`ghatana/services/media` remains the canonical runtime source. `ghatana-media` remains the migration and product-definition target until a signed, admitted transfer executes. Do not change that authority based on this checklist.

## Ordered completion gates

1. **Review Media-owned inventories and mappings (SUR-01…07, SUR-09).** Get named physical-surface and consumer owners to review the 26-candidate census, 17-consumer crosswalk, seven proposed compositions, and per-phase applicability. Keep SUR-08 and EXP-06 unavailable until Lifecycle publishes the required public contract.
2. **Close public dependency contracts (DEP-01…04).** Obtain immutable compatible package coordinates, digests, licenses, public contract versions, and the actual Shared/Platform owner decisions. Verify source-free installed consumers.
3. **Complete qualified implementation slices (RUN-01…10, EXP-01…05).** Bind identity, consent, artifact versions, jobs, external outcomes, product UI, and machine interfaces in small tested verticals. Missing infrastructure or owner contracts must remain `NOT_ADMITTED` until they exist.
4. **Admit migration (MIG-01…02), then normalize and execute it (MIG-03…04).** Freeze consumer parity first; obtain a signed per-path transfer/rollback manifest and execution window; make compatibility changes only after admission.
5. **Obtain independent acceptance and Lifecycle evidence (ACC-01…03, LC-01…02).** Record qualified reviewers, exact source revisions, findings and decisions; register/query only native Lifecycle receipts from its admitted APIs.
6. **Qualify and authorize release (REL-01…02).** Produce production artifact, security/license/profile, load/recovery/privacy evidence; run a staged canary with rollback; obtain explicit release-owner approval.

No later gate substitutes for an earlier one. In particular, implementation tests do not replace independent review, HTTP acknowledgment does not prove consumer processing, and package workspace links do not prove published artifacts.
