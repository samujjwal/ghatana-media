## Finding A — Require durable directory-entry acknowledgement

- **Priority / areas:** P1; Correctness, Tests/Coverage, Reliability/Resilience/Operability.
- **Where:** `adapters/agent-tools-media/src/main/java/com/ghatana/audio/video/tools/FileInvocationLedger.java`, `resolveDirectoryPath` / `createPrivateDirectoryIfAbsent` / `atomicWrite` / `claim` / `complete`.
- **Problem:** The former `forceDirectory` suppressed `IOException` and `UnsupportedOperationException`; `claim` could therefore return `CLAIMED` even though the directory entry was not confirmed durable before dispatch. Path setup also relied on recursive directory creation without syncing each containing parent or resolving existing symlink ancestors.
- **Root cause:** File bytes were forced while namespace durability was best-effort, and initial store hierarchy creation had no per-entry durability boundary.
- **Production-ready fix:** Added a package-private directory-sync seam while the public constructor always uses real filesystem sync. Existing ancestors resolve to canonical paths; new components are created one at a time and their containing parents are synced; the final store entry is synced even when it exists. The nearest pre-existing canonical ancestor is host-provisioned durable storage. Claim and completion propagate failed record-directory sync as unavailable/false.
- **Acceptance criteria:** Verified constructor sync failure at each of three created-parent positions; real public-constructor nested path claim and restart readback; claim sync failure yields `UNAVAILABLE` and zero binder dispatch; terminal sync failure yields UNKNOWN with exact identity/result safely replayed through a new ledger without another delegate call.
- **Path-scoped tests:** `FileInvocationLedgerTest`; `MediaToolExecutionBinderTest`; `AgentOutcomeAdmissionScenarioTest`; `AudioVideoToolHandlerFactoryAt05Test`.
- **Path-scoped evidence:** Focused Gradle test task under `DEV_SOURCE_COMPOSITE`, exact suite totals with zero skips/failures, plus `git diff --check`.
- **Evidence Generator enhancement:** None for this local implementation lane; no `.evidence/**` artifact is emitted.
- **Classification / convergence impact:** Current-state correctness gap. Fix improves local fail-closed safety but does not complete J-25 or change admission.

## Residual R1 — Hard-stop staging files

- **Priority / areas:** P2; Reliability/Resilience/Operability, Privacy/Data Governance.
- **Where:** `FileInvocationLedger.atomicWrite` creates `.inv-*.tmp` staging files before hard-link claim or atomic replacement.
- **Residual:** A hard process/host stop may leave a staging file. It is not a claim record; digest-named `.json` records remain the sole state. No startup or age-based cleanup is performed.
- **Safe bounded recovery:** Stop and verify all writer processes are quiescent; inventory staging-file names, sizes and SHA-256 values; delete only `.inv-*.tmp`; preserve `.json` records and `.lock` sidecars; retain a before/after inventory; restart and verify expected invocation readback. Both adapter READMEs now carry this procedure.
- **Convergence impact:** Documented operational residual; no dispatch safety or claim finality is inferred from a staging file.
