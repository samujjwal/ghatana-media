# Vision / Document Intelligence Consumer — Mandatory Surface Closure Matrix

**Scope:** Media's source-authorized scene-text path and its Java/TypeScript DI v1 consumer seams. This review does not claim a real DI worker, installed public client, OCR provider admission, or product acceptance.

**Review sources:** `AGENTS.md`; `.product-experience/pdp-0-product-truth/ocr-ownership.yaml`; `docs/architecture/MEDIA-OCR-DATACLOUD-DEPENDENCY-DECISION-2026-10-30.md`; `docs/migration/document-intelligence-media-crosswalk.md`; `docs/migration/ocr-consumer-inventory.v1.json`; `modules/vision/vision-service/README.md`; root `docs/{VISION,REQUIREMENTS,ARCHITECTURE,DESIGN,EXAMPLES,TESTING,EVIDENCE}.md`; current Java and TypeScript source/tests/build definitions; current Document Intelligence v1 source contract and client source in the sibling `ghatana` checkout.

**Final closure decision:** `not-converged-actionable`. MDI-001 ownership and the Media temporal/source boundary are clear. The Media repository has no installed, immutable compatible DI client dependency and no composed authenticated egress/consent binding. These are explicit blockers to runtime OCR, not grounds to create another protocol/client or call a stubbed test a positive result.

## Findings and acceptance

### F1 — No installed immutable DI client in the Media dependency graph

- **Priority:** P1; **areas:** architecture/design, requirements, API/contracts, generated parity, duplication, build/dependency, supply chain, compatibility.
- **Where:** `libs/audio-video-client/package.json`; `pnpm-lock.yaml`; `modules/vision/vision-service/build.gradle.kts`; `modules/vision/vision-service/src/main/java/com/ghatana/audio/video/vision/scenetext/DocumentIntelligenceV1.java`; `DocumentIntelligenceHttpClient.java`; source-only DI clients under sibling `ghatana/services/document-intelligence/clients/`.
- **Problem/root cause:** Media uses a structural TypeScript seam and a local Java HTTP/wire mirror; neither build consumes an immutable owner-published DI client. The current sibling Java client is `0.1.0-SNAPSHOT`; the TypeScript package peer is `@ghatana/document-extraction@0.1.0-SNAPSHOT`.
- **Production-ready fix:** DI owner publishes a compatible immutable client artifact and peer pair; Media consumes it through the published package/build boundary and removes duplicate transport/wire code after consumer conformance.
- **Acceptance:** Media's package/build graph resolves the published client without sibling source links; installed-package consumer test verifies the same frozen v1 schemas/provider catalog/parse/cancel behavior and negative responses.
- **Path-scoped tests:** DI package build/tests and installed consumer test; Media `authorized-scene-text`/scene-text adapter tests; Java consumer conformance.
- **Path-scoped evidence:** artifact version/digest, dependency lock resolution, source-free consumer logs, protocol fixture parity, and no Media-owned OCR provider.
- **Evidence Generator enhancement:** none; artifact publication/consumer install is the missing owner input.
- **Classification/convergence impact:** current-state gap. Runtime OCR remains NOT_ADMITTED until the immutable client can be consumed.

### F2 — Authenticated, consented DI egress is not composed

- **Priority:** P0; **areas:** architecture, correctness, security, privacy, feature completeness.
- **Where:** `ProductionVisionGrpcService.java:183-239`; `DocumentIntelligenceHttpClient.java:130-160`; `MediaRuntimeSceneTextSource.java:63-66`; DI `CredentialProvider` interface in sibling `services/document-intelligence/clients/java`.
- **Problem/root cause:** Media's production composition configures an allowlisted endpoint and local bounds but no DI credential provider; the Media HTTP client adds no `Authorization` header. More fundamentally, the current runtime source probe explicitly lacks MediaRuntime's external-processing-consent revalidator and refuses DI egress. Source rights do not imply consent to send image pixels to another service.
- **Production-ready fix:** after F1, bind the published client's credential provider to verified Shared identity for tenant/principal, and compose an owner-backed current purpose/consent egress revalidator that runs immediately before dispatch. Preserve exact source version/digest and report typed denial/unavailable/unknown outcomes.
- **Acceptance:** denied/missing/stale consent produces zero HTTP requests; tenant/principal credentials are scoped and never serialized into the frozen v1 body; allowed requests use TLS and the approved bearer credential; timeout/ambiguous response remains UNKNOWN; revoke immediately before dispatch blocks egress.
- **Path-scoped tests:** `SceneTextRecognitionServiceTest` plus a real/contract HTTP consumer test verifying auth header scope, consent ordering, no request on refusal, cancellation generation, and sanitized response errors.
- **Path-scoped evidence:** owner-published auth/consent contract, test trace proving zero requests on denial, request identity and source digest binding, and real source-free worker response under admitted test identity.
- **Evidence Generator enhancement:** none until the owner contract exists; then the integration evidence should capture the real consumer run.
- **Classification/convergence impact:** current-state safety blocker. Do not enable DI dispatch or claim OCR completion without this binding.

### F3 — Real DI positive consumer/provider proof is unavailable

- **Priority:** P1; **areas:** feature completeness, tests/coverage, repeatability, convergence.
- **Where:** `docs/migration/document-intelligence-media-crosswalk.md`; `docs/migration/ocr-consumer-inventory.v1.json`; task `media.dev.vision-document-intelligence`.
- **Problem/root cause:** current tests use typed fakes/in-process transports and validate mapping/failure semantics; Media has no installed client/auth binding and no admitted live DI worker/provider artifact.
- **Production-ready fix:** after F1/F2, run the same installed public client against a source-free DI worker and an owner-admitted real provider profile using rights-cleared image/frame fixtures; qualify output text/box mapping, source time, language, limits, cancel generation, timeout, unknown outcomes, and repeatability.
- **Acceptance:** real positive OCR lines and normalized boxes are tied to the exact Media artifact/version/frame/PTS/ROI; no invented confidence/read order/model identity; same DI gateway works for a second independent consumer; all adverse cases fail closed.
- **Path-scoped tests:** installed DI client worker consumer, Media scene-text Java/TS consumer suites, adversarial source/consent/version tests, and DI worker provider qualification selectors.
- **Path-scoped evidence:** worker/client/provider/model digests, rights-cleared fixture provenance, exact output/repeatability records, and independent consumer compatibility.
- **Evidence Generator enhancement:** no local collector can prove an unrun owner-qualified provider. Revisit only if the repo-native evidence system cannot capture actual installed consumer provenance after owner inputs exist.
- **Classification/convergence impact:** required positive acceptance remains blocked by owner admission; current tests prove boundary correctness only.
