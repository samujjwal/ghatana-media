## Findings

### F-04 — internal child projection omits bound child artifact/version identity

- **Priority:** P1
- **Area:** requirements/current-state alignment; feature completeness; correctness; API/contracts/config; tests/coverage
- **Classification:** current-state gap
- **Where:** `MediaRuntimeContracts.java:924-933`; direct regression location `MultimodalOperationSpecTest.java:213-248`.
- **Problem:** each internal fused child observation records job/request IDs, type, status, bounded result digest, and observations, but not its actual child artifact ID/version. Existing launcher checks bind rows to their declared child specs, but the internal projection drops that lineage.
- **Root cause:** result composition omits validated child identity while copying result observations. The direct test proves clock mapping/replay but does not assert internal child lineage.
- **Production-ready fix:** preserve the exact child source references in the internal composition only if the owning source/contract confirms their representation. Do not treat copying child IDs/versions as a product result, infer a result artifact/version, or add public field/schema semantics here. Resolve field placement with the exact PDP-1 output and aggregate boundary in F-03 first.
- **Acceptance:** after F-03 defines the owner-approved representation, deterministic fixtures preserve every child source identity without substituting child IDs for the result artifact's own identity; mismatched child/spec bindings do not yield a source-grounded success; replay remains stable.
- **Path-scoped tests:** extend `MultimodalOperationSpecTest` for any approved internal lineage representation, exact match/mismatch, and same-input replay. Add launcher restart readback only after authority recovery behavior in F-01 is addressed.
- **Path-scoped evidence:** contract test output, source fingerprint, selected-test manifest, JUnit XML, owner-approved contract compatibility result, and deterministic replay comparison. This proves internal composition only, not typed product output.
- **Evidence Generator:** proposed exact enhancement task `EG-MEDIA-RUNTIME-CONTRACTS-MULTIMODAL-FUSED-RESULT-PATH-SCOPE-001`: collect and validate changed-path fingerprint, selected contract tests, result-shape/compatibility checks, direct consumers, and replay parity; emit provenance-bearing artifacts and gate inputs. The repository checkout has no `tools/` tree or `discover-evidence-tools.mjs`; this task is a proposed missing capability, not an accepted Lifecycle work item.
- **Convergence impact:** blocks internal child-lineage closure only; by itself it cannot close PDP-1 product output or family aggregate semantics. Formal convergence remains blocked by F-01 through F-02 and owner-native Evidence Generator evidence.

### F-01 — restart reconciliation can persist success without current authority recheck

- **Priority:** P1
- **Area:** security; privacy/data governance/compliance; correctness; reliability/resilience/operability; tests/coverage
- **Classification:** current-state security/authority gap at the launcher consumer boundary
- **Where:** `launcher/src/main/java/com/ghatana/media/launcher/MediaRuntime.java:3827-3894`, especially source/child binding checks 3831-3841 and result persistence 3865-3894. The normal attempt path calls current authorization helpers around 1110-1177 and `requireCurrentSourceAuthorization` around 1355-1415; restart reconciliation does not call an equivalent current-authority check.
- **Problem:** restart recovery validates persisted tenant/principal/artifact/version/job bindings and terminal child states, but for all-completed children it rebuilds a successful fused result using a synthetic governance request and `ConsentDecision.unverified()` with `ProcessingBoundary.LOCAL`. A persisted prior authorization/child success is not a current authorization decision.
- **Root cause:** reconciliation is written as deterministic row recovery and has no authenticated current caller or persisted/revalidated authority evidence in this branch. It therefore cannot establish the source-owner authority that a newly persisted parent result requires.
- **Production-ready fix:** use an existing owner-authorized current-source authority recheck if one is defined for recovery and can bind the exact tenant, principal, source artifact/version, purpose, child plan, and effect. If that authority route or required inputs are absent, revoked, stale, or unavailable, keep parent finality `OUTCOME_UNKNOWN` and do not persist fused success. Do not reuse stale evidence, synthesize consent, or invent a system principal/recovery permission.
- **Acceptance:** after children complete, a revoked, stale, missing, or unavailable current authority response cannot persist `COMPLETED` or a fused parent result; only a currently allowed exact binding follows the existing durable success path. Child jobs are not redispatched during reconciliation.
- **Path-scoped tests:** extend `launcher/src/test/java/com/ghatana/media/launcher/MediaRuntimeMultimodalRestartTest.java` with revoked and unavailable authority cases and a positive exact-current-binding case, using deterministic local authority fixtures. Re-run the existing restart and PostgreSQL restart selectors only when their source paths are affected.
- **Path-scoped evidence:** launcher focused JUnit XML, source fingerprint, exact authority fixture tuple, before/after parent state and result readback, no-redispatch assertion, and restart replay comparison. Fixture authority is not real owner authorization evidence.
- **Evidence Generator:** included under proposed `EG-MEDIA-RUNTIME-CONTRACTS-MULTIMODAL-FUSED-RESULT-PATH-SCOPE-001` as a direct-consumer security/finality collector requirement; current authority itself remains an owner gate.
- **Convergence impact:** blocks trustworthy restart success and any durable product-result claim even if child lineage fields are added. Owner must define/authorize the recovery authority route before this can be closed safely.

It is not the closed typed output envelope and does not establish the result artifact's own immutable `artifactId`/`versionId`. Adding each child's artifact/version would still not satisfy the product output. Further, the legacy multimodal family intentionally defines no shared aggregate result contract.
- **Root cause:** the internal orchestration projection was used as a generic parent result without an exact capability-specific output conversion/persistence binding; the product family contract explicitly leaves aggregate identity and meaning undefined.
- **Production-ready fix:** keep `fusedResult` explicitly internal. Follow only an exact existing capability operation's typed success output and owning artifact persistence/reference path. If the use case requires a new cross-capability aggregate, hand the missing aggregate-output semantics to the PDP owner for definition before implementing a schema or field mapping. Do not define `artifactType`, result identity, provenance field placement, or shared family aggregate semantics in this runtime-contracts task.
- **Acceptance:** no internal `Map` is represented or documented as a completed PDP-1 typed cross-modal product output; any product path is validated against the exact closed schema and supplies the persisted result artifact's own `artifactId` and `versionId`; all five legacy RPC outputs remain mapped only to exact existing capability outputs, with no synthetic aggregate.
- **Path-scoped tests:** use existing PDP-1 operation/output schema validators and add owner-approved contract/consumer tests only after the typed operation and persistence binding are identified. Keep `MultimodalOperationSpecTest` explicitly scoped to internal composition. Add a negative boundary assertion that an internal fused map cannot pass as the typed output if the owning validator is available.
- **Path-scoped evidence:** exact PDP source revision, output schema-validation report, capability-to-output mapping, artifact persistence/readback tuple, direct consumer output, and owner-approved authority/readback evidence. No fixture-only map is accepted as a product artifact.
- **Evidence Generator:** proposed capability task must include output schema and typed-output validation. If the required aggregate contract remains undefined, mark the generator gate blocked on the owner source decision rather than emitting a locally invented schema.
- **Convergence impact:** blocks product-output convergence and family-wide completion. Child artifact/version fields in F-04 would close only internal source lineage, never the typed product result.

### F-02 — bounded child snapshot can omit fields silently and digest iteration-dependent subset

- **Priority:** P1
- **Area:** correctness; tests/coverage; reliability/resilience/operability; performance/scalability; repeatability/reproducibility
- **Classification:** current-state correctness/reproducibility gap in the internal projection
- **Where:** `MediaRuntimeContracts.java:1115-1150`, especially `boundedChildResult` 1118-1145 and `childResultDigest` 1148-1150.
- **Problem:** non-timing child result fields are visited in the input `Map` iteration order and silently skipped when their stringified value exceeds the remaining 8,192-character budget. The digest is then computed over only the surviving subset. If a caller supplies a map without stable iteration order, the retained fields and digest may differ; even with stable order, omitted fields have no explicit incomplete disposition, so a consumer can read a digest of a partial projection as if it covered the child result.
- **Root cause:** a storage/output size bound is implemented as best-effort field omission without canonical ordering or a completeness invariant. The digest authenticates the truncated view, not the full child result, and the output does not signal that non-timing data was dropped.
- **Production-ready fix:** canonicalize field traversal before applying deterministic limits and fail closed for the child projection if the existing bound prevents representing all required result fields. Do not claim a digest of a subset as a complete child-result digest. Any explicit truncation/partial-result payload semantics require the owning result contract; do not invent new status/field names here. Keep timed-observation truncation behavior aligned with its existing typed undetermined timing reason.
- **Acceptance:** equivalent maps with different insertion orders produce byte-identical projection/digest; over-budget non-timing content cannot yield a seemingly complete successful fused result; digest inputs are exactly the represented complete projection or the operation remains unresolved; existing bounded traversal remains finite.
- **Path-scoped tests:** extend `MultimodalOperationSpecTest` with reversed insertion-order fixtures, under/over-budget non-timing fields, and an assertion that truncation cannot be mistaken for complete result. Add provider/restart tests only if fail-closed projection changes parent finality.
- **Path-scoped evidence:** focused JUnit XML, deterministic serialized projection/digest comparison across insertion orders, bounds/adverse-input record, source fingerprint, and any parent finality/readback selector required by the change.
- **Evidence Generator:** include deterministic serialization/budget behavior in the proposed path-scoped result collector and repeatability gate. The actual product representation remains blocked under F-03.
- **Convergence impact:** current internal output is not guaranteed deterministic or complete for arbitrary valid child result map iteration/budget cases; this blocks repeatable fused-result evidence and must be repaired before any broader result contract can rely on it.
