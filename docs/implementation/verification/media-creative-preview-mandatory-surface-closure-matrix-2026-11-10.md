## Decision and acceptance boundary

**Decision: local implementation review only.** This matrix is not a convergence or closure verdict and does not assert PDP acceptance, runtime admission, qualification, or release status. Formal Evidence Generator/gtool closure is outside this local implementation lane. The selected consumer has documented local acceptance: one executable consumer should produce independently decoded PNG/GIF, WAV, GLB, and simulation outputs with local-preview labeling (`docs/development/USABLE-SURFACE-DELIVERY.md:53-66`). J-12's local renderer slice has decodable PNG frames, repeatability, exact clock and golden easing/pixel checks (`modules/production/animation/src/test/java/com/ghatana/media/production/animation/AnimationRendererTest.java:50-110`; `AnimationJ12LocalPreviewSliceTest.java:32-75`); the runnable example persists six PNGs plus GIF, independently reopens them, and binds hashes/source version/rational PTS/story ticks (`docs/development/remaining-work.json:2076-2078`). These prove local fixture behavior only. The J-12 task says “fixture-only simulation never counts” and stays `OPEN`, pending owner/source/tenant/rights/job/result and denial/cancellation/ambiguity/restart criteria (`docs/development/remaining-work.json:2056-2078`).

The broader registered task `M-BLD-V12.T01` remains `ASSIGNED_UNVERIFIED`, scoped to the full package. Its planned outcome includes real actor/tenant/source-rights/revision binding, real host plus source-free client, outcome recording, and restart/UNKNOWN (`docs/implementation/MEDIA-BUILD-WORK-PACKAGES.v1.json:72069-72078`; `docs/implementation/MEDIA-REMAINING-ONLY-OWNER-EXECUTION-2026-11-02.md:185`). Those integrated requirements are open; the local preview is not an acceptance substitute.

The J-12 web journey is explicitly a PDP-0 grounded proposal, not accepted; exact action/state/channel/runtime bindings remain pending (`.product-experience/pdp-3-product-experience/journey-contracts/animate-vector-or-procedural-scenes.yaml:7-11`). Its “accessible preview,” reduced-motion retention, and curve/time semantics appear as candidate success/postcondition text; verification has no required checks/evidence and is `not-run` (`.../animate-vector-or-procedural-scenes.yaml:42-73`). The associated screen contract labels accessibility intent as proposal pending owner review, and web/CLI channel bindings remain incomplete (`.product-experience/pdp-3-product-experience/screen-contracts/animate-media.yaml:358-360, 413-445, 454-459`). The consumer is a CLI/file producer, not that browser/editor UI. Therefore an accessible interactive preview and reduced-motion UI are **improvement backlog**, not current acceptance criteria for this local consumer. Do not infer owner-approved visual design, accessibility behavior, or runtime authority from proposal text.
